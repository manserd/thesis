\section{Automated Planning}

\kw{Automated planning} is a branch of Artificial Intelligence research concerned with automated problem-solving. Given some formal representation of an environment, the objective is to find a sequence of actions which transforms the environment from some initial configuration to some desired end configuration.

\section{Planning Tasks}

To reason about an automated planning problem, we want a formal representation of the environment in which the problem exists. One way to achieve this is by describing the environment via a finite set of ``properties'', such that every configuration of the environment is represented by some assignment of values to these properties.

%Example?

Let \kw{state variable} refer to such a property of the environment, and let $V$ refer to the finite set of all state variables used to model an environment, with each $v\in V$ having a finite, non-empty \kw{domain} $\Dom(v)$ of possible values.

Let \kw{partial assignment} refer to a function $l$ defined on some $\Vars(l)\subseteq V$, with $l(v)\in\Dom(v)$ for all $v\in\Vars(l)$; let \kw{state} refer to a partial assignment $s$ with $\Vars(s)=V$. We say a state $s$ \kw{satisfies} a partial assignment $l$ if $s(v)=l(v)$ for all $v\in\Vars(l)$.

Let \kw{action} refer to a tuple $o=\langle\Pre_o,\Eff_o\rangle$ of partial assignments, with $\Pre_o$ the \kw{preconditions} of $o$ and $\Eff_o$ the \kw{effects} of $o$.

Then a \kw{planning task} is a tuple $$\Pi=\langle V,\Dom,I,G,A\rangle,$$ with $I$ a state called the \kw{initial state}, $G$ a set of partial assignments called the \kw{goals}, and $A$ a finite set of \kw{actions}.

An action $o$ is \kw{applicable} in a state $s$ if $s$ satisfies $\Pre_o$. \kw{Applying} an applicable action $o$ in a state $s$ produces the state $s[o]$ with $$s[o](v)=\begin{cases}\Eff_o(v)&\text{if $v\in\Vars(\Eff_o)$,}\\s(v)&\text{otherwise,}\end{cases}$$ for all $v\in V$.

\section{State Spaces}
\label{sec:sss}

While planning tasks allow us to represent an automated search problem in a compact manner, it can be easier in some cases to use a representation that places more emphasis on states rather than actions.

Consider a planning task $\Pi=\langle V,\Dom,I,G,A\rangle$.

The \kw{state space induced by $\Pi$}, $\calS(\Pi)$, is a tuple $\langle S,\Succ,s_I,S_G\rangle$ with components defined as follows:

\begin{itemize}
    \item the finite\footnote{$V$ is finite and $\Dom(v)$ is finite for all $v\in V$. Thus $|S|=\prod_{v\in V}|\Dom(v)|$.} set of \kw{states} $S$ is the set of all possible states: $$S=\{s\mid s\text{ is a state}\};$$
    \item the \kw{successor generator function} $\Succ:S\ar\calP(S)$, with $\calP$ denoting the power set, gives all \kw{successors} of a state, that is, for a state $s\in S$, $\Succ(s)$ contains all states that can be produced by applying some applicable action $o\in A$ in $s$: $$\Succ(s)=\{s[o]\mid o\in A, o\text{ applicable in }s\};$$
    \item the \kw{initial state} $s_I$ is $I$;
    \item the set of \kw{goal states} $S_G$ is the set of states that satisfy every $g\in G$; we call such a state a \kw{goal state}: $$S_G=\{s\in S\mid s\text{ is a goal state}\}.$$
\end{itemize}

Some additional definitions are helpful.

A \kw{path} from $s_1\in S$ to $s_n\in S$ is a tuple $\pi=\langle s_1,\ldots,s_n\rangle$, with $n\geq 1$, where $s_{i+1}\in\Succ(s_i)$ for all $1\leq i<n$, and which we say has \kw{length} $|\pi|=n-1$. The set of \kw{paths} from $s_1\in S$ to $s_n\in S$ is $P(s_1,s_n)=\{\pi\mid \pi$ is a path from $s_1$ to $s_n\}$. We say a state $s'$ is \kw{reachable} from $s$ if there exists some path from $s$ to $s'$.

A \kw{partial solution} from $s\in S$ is a path $\phi$ from $s$ to any goal state $s_G\in S_G$. The set of \kw{partial solutions} from $s\in S$ is $\Phi(s)=\{\phi\mid\phi$ is a partial solution from $s\}$. A \kw{solution} is a partial solution from $s_I$.

The \kw{goal distance} of $s\in S$ is $h^*(s)=\min_{\phi\in\Phi(s)}|\phi|$, with $h^*(s)=\infty$ if $\Phi(s)=\emptyset$.

\section{State Space Search}

A \kw{state space search algorithm} (or simply \kw{search algorithm}) is an algorithm that explores a given state space in search of a solution. A \kw{semi-complete} search algorithm is a search algorithm that is guaranteed to find a solution if one exists. A \kw{complete} search algorithm is a semi-complete search algorithm that is guaranteed to terminate if no solution exists.

Another property commonly used to classify search algorithms is \kw{optimality}: a search algorithm is considered \kw{optimal} if it always finds a solution with minimal path length among all solutions. In this work, optimality does not concern us\footnote{Not directly, at least: we primarily aim for a small runtime, and while a solution of any path length is satisfactory, long solution paths might take longer to find.}: we are simply concerned with finding any solution at all, which is sometimes called \kw{satisficing search}.

A search algorithm requires a mechanism that can track which states the algorithm has encountered but not yet explored, and which can tell the algorithm which state to explore next. Going forward, we will refer to such constructs as \kw{open lists}.

An \kw{open list} $O$ is a container to which we can add a state $s$ via $O.\Add(s)$, from which we can remove (and receive) an arbitrary state using $O.\Remove()$, and for which we can check whether it is empty via $O.\Empty()$. We may also use $s\in O$ to refer to any state $s$ contained in open list $O$.

A generic skeleton for a complete\footnote{Completeness follows from the finiteness of $S$ and the use of the \textit{closed} set.} state space search algorithm is given in \cref{alg:sss}.

\begin{algorithm}[H]
    \caption{State space search}
    \label{alg:sss}
    \begin{algorithmic}[1]
        \Require A state space $\calS=\langle S,\Succ,s_I,S_G\rangle$.
        \Ensure A solution if one exists, otherwise \textbf{unsolvable}.
        \State \var{open} \ceq \New open list
        \State \var{closed} \ceq \{\}
        \State \var{open}.add($s_I$)
        \While{\Not \var{open}.empty()}
        \State $s$ \ceq \var{open}.remove()
        \If{$s$ $\notin$ \var{closed}}
        \State \var{closed} \ceq \var{closed} $\cup$ \{$s$\}
        \If{$s\in S_G$}
        \State \Return path from $s_I$ to $s$
        \EndIf
        \ForAll{$s'\in\Succ(s)$}
        \State \var{open}.add($s'$)
        \EndFor
        \EndIf
        \EndWhile
        \State \Return \textbf{unsolvable}
    \end{algorithmic}
\end{algorithm}

\section{Greedy Best-First Search}
\label{sec:gbfs}

Consider for a moment a scenario where you are in your car, with the goal of reaching some city, and without prior knowledge of the area and without access to a map. If your behavior resembled that of a random search, your strategy to reach the city would be taking random turns until you end up at the destination by chance (or because you drove down every possible road). Of course, this is not a particularly good strategy.

Luckily, there is a better way: people that have explored this area before have installed markers indicating roughly how far away you are from the city. Naturally, if you prioritize turns such that the distance indicated on the markers goes down, you will likely reach your destination much faster.

This analogy illustrates the idea of a \kw{heuristic}: for a state space $\calS=\langle S,\Succ,s_I,S_G\rangle$, a \kw{heuristic} is a function $$h:S\ar\bbN_0\cup\{\infty\}$$ that maps each state $s\in S$ to an estimate of its goal distance $h(s)$.

A \kw{greedy best-first search}[GBFS] algorithm is a best-first search algorithm using the evaluation function $h$.

\section{High-Water Mark}

Consider, for a moment, this thought experiment: say you are observing GBFS traversing a single path from some starting state to a goal state, and imagine a pool of water whose water level rises and falls relative to the heuristic value of the state which GBFS is currently at. Now consider that, as GBFS arrives at the goal state with the pool fully drained, the walls of the pool show a transition from wet to dry at a height corresponding to the maximum heuristic value encountered by GBFS along the path.

We call this maximum heuristic value the \kw{high-water mark} for this path: for a state space $\calS=\langle S,\Succ,s_I,S_G\rangle$ and a heuristic $h$, the \kw{high-water mark} of $h$ is a function $\Hw_h:\{\pi\mid\pi\text{ is a partial solution from any }s\in S\}\ar\bbN_0\cup\{\infty\}$ such that $$\Hw_h(\pi)=\max_{s'\in\pi}h(s'),$$ or informally, the high-water mark represents how high $h$ must climb before arriving at the goal state.

Recall that the set of partial solutions from any $s\in S$ is $\Phi(s)$. We define the high-water mark for an individual state $s$ such that $$\Hw_h(s)=\begin{cases}\min_{\pi\in\Phi(s)}\Hw_h(\pi)&\text{if }\Phi(s)\neq\emptyset,\\\infty&\text{otherwise,}\end{cases}$$ that is, the high-water mark for an individual state $s$ is the smallest high-water mark along any path from $s$ to a goal state.

\section{Bench Transition System}

Let $\calS$ refer to some state space $\langle S,\Succ,s_I,S_G\rangle$ and let $h$ refer to some heuristic.

Consider what the high-water mark of some state $s$ tells us about GBFS' behavior, assuming $s$ is the state in the open list with the smallest heuristic value: since a high-water mark of $\Hw_h(s)$ guarantees that there exists a partial solution along which $h$ will never climb above $\Hw_h(s)$, we can be sure that GBFS will never expand a state $s'$ with $h(s')>\Hw_h(s)$, since there will always be a state $s''$ with $h(s'')\leq\Hw_h(s)$ in the open list, which GBFS will prefer because $h(s'')<h(s')$. This insight naturally leads to a notion of ``heuristic progress'' for GBFS: we say a state $s$ is a \kw{progress state} if $\Hw_h(s')<\Hw_h(s)$ for at least one $s'\in\Succ(s)$.

\section{Uninformed Heuristic Regions}
\label{sec:uhr}

All heuristics (short of the \kw{perfect heuristic}, which is a mostly theoretical heuristic that always gives the true goal distance) are inherently inaccurate: nonetheless, having an estimate of the goal distance, even if not entirely accurate, is still vastly better than searching blindly in most situations. Note, however, that we said \textit{most} situations.

Consider a similar scenario as in \cref{sec:gbfs}, but this time, you ask a route planning service for directions to the city. The service provides you with two options: route A, which it estimates will take around five minutes, and route B, which it estimates will take around ten minutes. You do not care particularly much about this five-minute difference, but in the absence of a reason that speaks against taking the shorter route, you select route A. After twenty minutes of following route A, you are still not at your destination. You check the route planning service, and it now estimates you will arrive in four minutes. Driven by your deep trust in this route planning service, you keep following route A. Another twenty minutes pass without you reaching the city, and then another twenty minutes, until you finally reach the destination after an hour of driving.

Two things happened here: first, the estimate given by the route planning service was wildly inaccurate, prompting the driver to pick route A, which ended up taking much, much longer than route B would have taken (assuming the estimate of ten minutes for route B was reasonably accurate). If we take this route planning service to represent a heuristic function, this describes the concept of an \kw{uninformed heuristic region}[UHR], which is a region in a state space where the heuristic provides severely misleading estimates of the goal distance.

But the route planning service (ergo, the heuristic) is not the sole reason the driver ended up taking an hour to reach their destination. Any person caught in this scenario would have likely stopped trusting the estimate for route A after a while and would have pivoted to a different strategy. This is the second idea this analogy aims to illustrate: GBFS' tendency to stubbornly trust the heuristic can trap the algorithm in UHRs. To be clear: the driver (ergo, GBFS) eventually arrived at the destination regardless; but what if the destination had been an important meeting, set to begin half an hour before the driver reached the city (think a strict limit for how long a search is allowed to run before being terminated)?

\section{Stochastic Exploration}

Keeping with the analogy outlined in \cref{sec:uhr}, we can start thinking about ways in which a person might ``escape'' route A. One very simple idea is that the driver could simply decide to ignore the route and instead take a random turn\footnote{It should be noted that this analogy only vaguely mirrors how an actual search algorithm would explore such an environment. Most importantly, a search algorithm, unlike our driver, has no notion of being ``at'' a single position: instead we tend to talk of a ``frontier'', which can be pictured like an endless army of ants exploring a maze, with one ant able to take one step for every step of the algorithm. The important consequence of this is that the ``random turn'' our driver is taking can be any unexplored turn along the entire route they have so far driven.}, hoping that this will lead them to a location where the route planning service provides more helpful estimates.

This act of ``taking a random turn'' is done in pursuit of \kw{exploration}, that is, selecting states that might not immediately lead to a smaller goal distance, but which may broaden the pool of states available for us to consider in subsequent steps. Exploration ideally acts to enable more effective \kw{exploitation}, that is, selecting the most ``promising'' states, i.e. those states we deem to be closest to a goal state.

\kw{Stochastic exploration}, then, is the term we use to refer to this idea of ``occasionally taking a random turn'' we described above. More precisely, a GBFS algorithm that performs stochastic exploration occasionally ignores the advice of the heuristic in favor of selecting a random state. Note that the terms ``occasionally'' and ``random'' are deliberately left vague here, since different ways of adding stochastic exploration to GBFS work differently in this regard: we will be more precise when discussing concrete applications of stochastic exploration.

Stochastic exploration has been shown to be a useful way to allow GBFS to ``escape'' UHRs.

When we speak of \kw{escaping} a UHR, we mean finding a state $s$ outside the UHR such that future exploitation will prefer $s$ over states within the UHR.
 
\section{$\epsilon$-GBFS}

Let $\calS$ be some state space $\langle S,\Succ,s_I,S_G\rangle$.

An \kw{open list selector function} is a function $q:\{O_1,\ldots,O_n\}\ar\{1,\ldots,n\}$, with $O_i$ an open list for all $1\leq i\leq n$: the nature of how a queue selector function decides which result to produce will be specified when such a function is instantiated.

%This definition makes $q$ look like a pure function, which it isn't.

A \kw{multi-queue open list} $O$ with open lists $\calO=\{O_1,\ldots,O_n\}$ and open list selector function $q$ is an open list where, for any state $s\in S$, $O.\Add(s)$ implies $O_i.\Add(s)$ for all $1\leq i\leq n$, $O.\Remove()$ implies $O_{q(\calO)}.\Remove()$, and $O.\Empty()$ is true if and only if $O_i.\Empty()$ is true for all $i$.

An \kw{$\epsilon$ open list} with open lists $\calO=\{O_1,O_2\}$ and \kw{probability} $\epsilon\in(0,1)$ is a multi-queue open list with open lists $\calO$ and an open list selector function $q$ such that $$q(\calO)=\begin{cases}1\text{ with probability $\epsilon$,}\\2\text{ otherwise.}\end{cases}$$

Then a \kw{$\epsilon$-GBFS} algorithm is a state space search algorithm that uses an $\epsilon$ open list with open lists $O_1,O_2$, where $O_1$ is an unbiased open list and $O_2$ is an open list sorted by some heuristic $h$.

\section{Type-GBFS}

Consider a situation where $\epsilon$-GBFS' open list is dominated by states within a UHR. Our scenario from \cref{sec:uhr} can work to illustrate how this might happen: if the start of route B is one state in the open list, and we say route A adds new states to the open list, each still in the same UHR as route A, for every crossing the driver passes, then it is easy to see that the longer the driver stays on route A, the more the open list fills with states in the UHR, while the number of states outside it remains at just one.

Since the unbiased open list, which $\epsilon$-GBFS' uses for exploration, selects states uniformly at random, that selection will be heavily biased towards states still within the UHR, making it hard for the algorithm to escape the region. One way to mitigate this is by considering ``similar'' states as part of the same ``group'', and then first selecting a group before finally selecting a state from that selected group.

A \kw{type system} dictates the rules by which the states in an open list are disjointly partitioned into \kw{types}, where a \kw{type} is a subset of the states in the open list. A \kw{type selection strategy} dictates how a type is selected for a subsequent removal of a state. A \kw{state selection strategy} dictates how a state is selected for removal, given a previously selected type.

A \kw{type-based open list} following type system $\bbT$, type selection strategy $\cdot^t$, and state selection strategy $\cdot_s$, is an open list whose states are disjointly partitioned into types according to $\bbT$, and where $O.\Remove()$ first selects a type according to $\cdot^t$, and then selects and removes a state from that type according to $\cdot_s$.

An \kw{alternating open list} $O$ with open lists $\calO=\{O_1,O_2\}$ is a multi-queue open list with open lists $\calO$ and an open list selector function $q$ such that $$q(\calO)=\begin{cases}1\text{ if }i\;\%\;2=0,\\2\text{ otherwise,}\end{cases}$$ where $i$ is the total number of completed invocations of $O.\Remove()$ since the instantiation of $O$, and $\%$ is the modulo operator\footnote{For any $n\in\bbN_0,m\in\bbN_1$, $n\;\%\;m$ is the remainder of the integer division $n\div m$.}.

Finally, a \kw{Type-GBFS} algorithm using type-based open list $O_1$ is a state space search algorithm using an alternating open list with open lists $O_1,O_2$, where $O_2$ is an open list sorted by some heuristic $h$.

\section{The HG Type System}

The \kw{HG type system} is a type system that considers those states $s$ part of the same type which have the same heuristic value $h$ and for which the path from $s_I$ to $s$ along which they were encountered has the same length.

The \kw{$\cdot^U$ type selection strategy} is a type selection strategy that selects types uniformly at random. The \kw{$\cdot_U$ state selection strategy} is a state selection strategy that selects states uniformly at random. This gives us our first concrete variant of Type-GBFS: the \kw{HG$^U_U$} algorithm is the Type-GBFS algorithm using a type-based open list following the HG type system, the $\cdot^U$ type selection strategy, and the $\cdot_U$ state selection strategy. We will use notation like this to refer to future variants of Type-GBFS as well: going forward, TS$^\text{TSS}_\text{SSS}$ shall refer to Type-GBFS using a type-based open list following some type system TS, some type selection strategy TSS, and some state selection strategy SSS.

Recall the beginning of \cref{sec:uhr}, where we propositioned that, in most situations, following the heuristic is still preferable to ignoring it completely. Following that logic, we might want a type-based open list that places a bit more weight on states with smaller heuristic values, in such a way that those states are generally more likely to be selected, but that still allows for occasional selections that go entirely against the advice of the heuristic.

We will first generalize this idea to be able to describe a type selection strategy that can use any value, not just a heuristic value, to determine the ``weight'' of a type. We first introduce the idea of a \kw{type property}: a \kw{type property} is a function $\delta:\calT\ar\bbN_0\cup\{\infty\}$ defined for all types $\calT$ induced by some type system. A \kw{biased type selection strategy} biased by type property $\delta$ is a type selection strategy that selects a type from among the \kw{qualifying types} uniformly at random, where the \kw{qualifying types} are all those types $T$ in the open list with $\delta(T)=b$, and $b$ is chosen from the set $B$ of all distinct $\delta(T)$ with the probability of choosing each $b'\in B$ given by $$\Softmin(b')=\frac{\exp(-b'/\tau)}{\sum_{b''\in B}\exp(-b''/\tau)},$$ with $\tau>0$.

The \kw{min-h type property} is a type property where, for any type $T$ induced by some type system, $\text{min-h}(T)=\min_{s\in T}h(s)$, with $h$ the heuristic. Finally, the \kw{H type selection strategy} is the biased type selection strategy biased by the min-h type property. This finally allows us to describe the HG$^H_U$ algorithm, which puts into practice this idea of still listening to the heuristic in some capacity during exploration instead of ignoring it completely like HG$^U_U$ does.
